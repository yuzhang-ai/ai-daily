# 选题标准

这份标准从产品君（B 站 / 抖音「盘点一周AI大事」）2026 年 2–11 月的 41 期周报反推而来，再按本日报的定位收窄。周报样本：41 期、460 条，平均每期 11 条。

## 一、产品君选什么

| 类别 | 占比 | 例子 |
|---|---|---|
| 旗舰模型发布 / 升级 | 约 26% | Claude Opus 4.6、Gemini 4 Carbon、GPT-5.3 Codex |
| 研究员 / 学术开源 | 约 20% | 「研究员开源最强配音模型 Just-Dub-It」 |
| 视频 / 图像 / 音频 / 3D 模型 | 约 17% | Seedance 2.0、Qwen-Image-2.0 |
| 编码与 Agent 工具 | 约 9% | Codex 桌面版、Claude Cowork、WebMCP |
| 世界模型 / 机器人 | 约 4% | Genie 4、Project Genie |
| 现象级产品 / 社区爆火 | 少但播放最高 | AI 狼人杀、AI 雇佣人类平台 RentAHuman |

规律：

1. **只写「发生了什么」**：动作几乎都是「发布 / 开源 / 上线 / 升级」，不写评论、融资、人事八卦、政策争论。
2. **大厂优先**：Google、OpenAI、Anthropic 三家合计约 30%；国内阿里、字节、DeepSeek、Kimi、智谱、MiniMax 稳定出现。
3. **开源占三分之一**：「开源」是出现最多的动作（153 / 460）。
4. **用户能摸到**：选的是能用、能下载、能试的东西，期货和传闻很少。
5. **播放最高的几期都是「AI 进入生活」的现象**（AI 相亲、AI 当老板、龙虾越狱跑滴滴），不是参数最高的模型。

## 二、我们和产品君的差别

产品君面向泛科技受众，追求「最强」「炸裂」；本日报面向关注 AI 行业、想看懂趋势的读者，篇幅只有 3 条，所以：

- **收窄**：研究员个人开源、学术 demo、纯图像 / 视频模型刷榜，产品君会写，我们默认不写。除非它代表一个新能力第一次可用，或者被大量产品采用。
- **加深**：每条要能回答「这件事改变了什么」。产品君一行字，我们要写清机制、数字和影响。
- **不写「最强」**：措辞用具体数字和对比，不用「最强」「炸裂」「王炸」。产品君 460 条里有 114 条带「最强」，这是短视频标题的写法，不适合文字日报。

## 三、打分

每个候选事件按五项打分，每项 0–2 分，满分 10 分。

| 维度 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|
| 影响面 | 改变很多人正在用的产品，或定义一个新品类 | 影响某一类开发者 / 某个行业 | 只影响少数人 |
| 一手可验证 | 官方博客 / 论文 / 仓库 / 文档可直接查到 | 只有可信媒体报道 | 只有截图、爆料、二手转述 |
| 新信息量 | 新能力、新价格、新形态，第一次出现 | 已有能力的明显升级 | 换皮、小版本、重复宣传 |
| 能动手 | 今天就能用、能下载、能调 API | 有候补名单 / 灰度 | 只是预告 |
| 讨论热度 | 3 个以上独立来源报道，或 HN 300 分以上 | 2 个来源，或 HN 100 分以上 | 单一来源 |

**入选门槛 6 分**。分数相同时，按这个顺序取舍：一手可验证 > 影响面 > 能动手。

## 四、直接排除（噪声）

- 客户案例、合作伙伴新闻稿（「XX 公司用 ChatGPT 提升了效率」）
- 企业社会责任、教育公益、节日活动
- 融资、估值、IPO、财报，除非它直接改变产品或定价（IPO 本身不写）
- 人事变动、高管言论、八卦、诉讼
- 「据知情人士」「泄露」「疑似」类传闻，除非官方当天证实
- 优惠、限额重置、促销活动
- 基准刷榜但没有可用产品的论文
- 同一事件的第二、三篇报道：合并到一条，链接列在来源里

## 五、去重

- 同一事件跨来源出现：采集脚本已按链接和标题合并。仍要人工看一遍：同一产品的「发布」和「定价」「上线到某平台」是同一件事。
- **近 7 天已写过**的事件（候选池标「近 7 天已写」）：只有出现新的实质信息（正式开放、价格公布、开源权重）才再写，并在正文第一句说明「上周预告的 XX 今天正式开放」。
- 同一天同一家公司在要闻里最多 1 条，除非两件事完全不相关且都在 8 分以上。快讯不受此限。

## 六、配比

3 条要闻尽量覆盖不同类型，参考：

- 1 条模型 / 平台（大模型、多模态、开源权重）
- 1 条产品 / 工具（Agent、编码工具、应用功能）
- 1 条不限：开源、研究、现象级应用、国内厂商

当天确实只有一类大新闻时可以不平衡，但要在「今日一句话」里点明「今天是 XX 的一天」。

## 七、开源项目

「值得研究的开源项目」放 2–3 个，标准：

- 必须满足其一：当天 GitHub Trending 或 HF 趋势榜上有它；或者它是当天要闻、快讯里首次出现的新仓库。创建超过 30 天、当天又不在榜上的成熟项目不选，再有名也不选，那是「推荐库」不是「今天值得看」。
- 和 AI 应用开发相关：Agent 框架、工具、模型推理、评测、技能包
- README 清楚，能在 10 分钟内跑起来或看懂
- 排除：加密货币、股票分析机器人、纯资源合集（awesome-xxx）、教程集

## 八、季度复核

每个季度用产品君最近 10 期周报检查一次这份标准有没有过时。取数和对照已经是脚本：

```bash
python3 -I skill/ai-daily/scripts/review_quarter.py --weeks 10 --save work/cpj-weekly.json
```

脚本做的事：用 B 站公开搜索接口取产品君最近 N 期「盘点一周AI大事」，把每期视频简介按行拆成条目；每条和那一周（视频发布日往前 7 天）的本日报标题对照，分四类：**已写**、**候选池有，被淘汰**（对照每期提交的 `logs/triage-DATE.md`，本地有 `work/candidates-DATE.json` 时也一并算）、**候选池没有**、**无候选池记录**（那几天没有 triage 表）。结果写到 `work/review-DATE.md`：四类的条数和占比、类别分布表、逐条清单。`--from-json work/cpj-weekly.json` 离线重跑，不再请求 B 站。

拿到报告后人工做三件事：

1. 「候选池没有」超过 3 成：信源有缺口，在 `scripts/collect.py` 的 `SOURCES` 里补信源。报告的「判断」一节直接给出这个比例。
2. 读「候选池有，被淘汰」清单，如果有本该写的大事，回头看是哪一项打分偏低，调整第三节的打分说明。
3. 报告里的类别占比和第一节的表格相差超过 10 个百分点时，更新第一节的表格。

匹配按标题关键词做（两个共有的具体词，或一个 6 字以上的产品名），换了说法的同一件事会被算成「未写」；拿不准的条目去 `outputs/` 里 grep 一下再定。
