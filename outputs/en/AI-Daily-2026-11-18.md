### 3. Anthropic: Linked billing enters beta on the Claude Platform, without taking the customer's API key
- Sources: [Product post](https://claude.com/resources/articles/linked-billing-on-claude-platform); [Developer docs](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)
- Type: Product update
- Rating: ★★★★☆
- Summary: Linked billing on the Claude Platform is in beta. A third-party app can let a customer pay for API usage with that customer's own Claude organization, and the customer's API key is not handed to the app.
- Key figure: 19 | platforms the announcement names as already supported

**Why it matters:** When an app calls Claude for a customer, the usual path has been for the customer to hand over an API key. Once the key is held elsewhere, whoever has it can create requests billed to the customer, and the app has to store, encrypt, and rotate it. Linked billing changes that to a link between the customer's Claude organization and the app, with usage billed directly to the organization. The customer approves each app, can set a spend limit, and can unlink at any time. On each request, the app chooses whether it pays or the customer pays.

**Key points:**
1. The product post names 19 platforms that already support it, including Linear, Warp, Ramp, Asana, and Railway. The customer uses Anthropic's hosted approval flow. The docs say an Owner, Admin, or Billing role can approve, and that individual developers and large teams use that same step. Usage can then draw on an existing commitment or be pay-as-you-go.
2. Requests run in the app's own organization. The docs say the customer's IP allowlists, encryption keys, and data retention therefore do not apply, and neither do zero data retention, a business associate agreement, or customer-managed encryption keys. The docs say usage that needs HIPAA, FERPA, or customer-managed encryption key coverage should not go through this path.
3. Only organizations that pay Anthropic directly for API usage can be billed this way. Prepaid credits and invoices both count. The docs say some promotional credits cannot pay for these requests. The ones named are the monthly API credits that come with Claude Max, Ultra, and Team, and credits from Anthropic's partner, VC, and startup programs. Organizations billed through the AWS, Google Cloud, or Azure marketplace cannot. An account that has only a Claude subscription, and no billable API organization, cannot either. Those requests are refused with a 403. If the customer cannot be billed, the request is refused rather than charged to the app.

**What it means:** The old interface for a third-party app was bring-your-own-key: the customer handed over a key and the app kept it. On November 16, Hugging Face stopped accepting a caller's own provider key for text inference and let the platform choose the provider. Anthropic today is the other end of that. The key does not have to be handed over, the bill goes back to the customer's own Claude organization, and execution stays in the app's organization. The teams affected are the ones calling Claude inside someone else's coding tool or automation product without wanting to give that product a long-lived key. Organizations billed through a cloud marketplace, holding only a subscription, or relying on the promotional credits named above, cannot use this path.

**Risks and open questions:** The docs call this a beta. Endpoints, parameters, and behavior can change, and it may not be suitable for production. The customer's own data-protection terms do not follow the request. A request billed to the customer cannot use billable code execution. The API returns a 400, and those requests have to be billed to the app. Message Batches cannot currently bill the customer. A batch item that tries to do so errors, and neither side is billed for that item. When nothing on the account can pay, the API can refuse the request with a 402, and the response does not say whether the reason is a lack of credit. The 19 platforms are names in the announcement. This issue did not sign in to each one. The Next Web restated the post before the collection cutoff. That restatement is not an independent test.
