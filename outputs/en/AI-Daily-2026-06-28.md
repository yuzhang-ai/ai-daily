# AI Daily 2026-06-28

## One-liner

> The competitive point of AI products is shifting from "whether the model is smart" to "who can organize tasks, context, permissions, cost, evaluation and human review into a delegable work system".

## Top stories

### 1. Anthropic: Economic Index report, Cadences
- Sources: [Anthropic report](https://www.anthropic.com/research/economic-index-june-2026-report); [Official PDF](https://cdn.sanity.io/files/4zrzovbb/website/9e0eadc8097864886c5d5060ebb1f89b02ea29d6.pdf); [Local copy](sources/anthropic-economic-index-cadences-2026-06-26.pdf)
- Type: Research report
- Rating: ★★★★★
- Summary: Using finer-grained Claude usage data, Anthropic shows that AI use is shifting from chat Q&A toward delegable artifact production and long-running agentic tasks.

**Why it matters:** The report is valuable to AI product managers because it goes beyond "can AI do it" and breaks down when users turn to AI, what they produce, how much autonomy they hand over, and how users perceive changes to their work over the next 12 months. It pulls judgments about agent products back from subjective impressions to data.

**Key points:**
1. The shape of Claude usage is changing: the report states that with the growth of Claude Code and Cowork, many sessions are no longer simple chat transcripts but long-running agentic tasks.
2. Product form matters more than the model itself: for the same artifacts such as code, scripts and websites, AI autonomy on Claude Code is clearly higher than in chat/Cowork, and the gap remains even when the same model is compared.
3. High-value work consumes more compute: looking at artifacts, token consumption and a wage proxy together, the report finds that complex artifacts such as apps/websites consume far more than the median; people who use AI more for automation are more optimistic about its effect on the value of their skills, but the report also cautions that skill erosion cannot be ruled out.

**What it means:** When judging an AI product from now on, do not only ask "how strong is the model"; ask what artifacts it can reliably produce, how much judgment users are willing to delegate, and whether it preserves human review and context.

**Risks and open questions:** The report is based on Anthropic's own privacy-protected data and does not represent the whole market; the greater optimism of automation users may reflect self-selection bias.

### 2. OpenAI: Previewing GPT-5.6 Sol, a next-generation model
- Sources: [OpenAI page](https://openai.com/index/previewing-gpt-5-6-sol/); [GPT-5.6 Preview System Card](https://deploymentsafety.openai.com/gpt-5-6-preview); [Official PDF](https://deploymentsafety.openai.com/gpt-5-6-preview/gpt-5-6-preview.pdf); [Local copy](sources/openai-gpt-5-6-preview-system-card-2026-06-26.pdf)
- Type: Official blog / System card
- Rating: ★★★★★
- Summary: OpenAI previews GPT-5.6 Sol/Terra/Luna; the point is not "another model" but that reasoning effort, subagents, agentic coding evals and tiered safety release mechanisms are becoming new product infrastructure.

**Why it matters:** This is a signal for the shape of AI products over the next 3-12 months. OpenAI puts `max` reasoning effort, `ultra` subagent mode, Terminal-Bench 2.1, cyber/bio safeguards and trust-based access into a single release narrative, which says that advanced agent capability will increasingly depend on "capability tiers + safety stack + tiered access + evals".

**Key points:**
1. GPT-5.6 is not a single model but three tiers, Sol, Terra and Luna; Sol starts as a small trusted preview, with broader availability planned later.
2. The new capabilities point clearly toward agents: `max` gives complex tasks more reasoning time, `ultra` speeds up complex work through subagents, and the coding evaluations emphasize terminal workflows, planning, iteration and tool coordination.
3. The system card turns safety into a product layer: in-model refusals, real-time classifiers, account-level risk signals, trust-based access, automated red teaming, user confirmation for computer use, and protection against data-destructive actions.

**What it means:** Future enterprise agent products cannot be just a "start" button; they need task difficulty tiers, permission boundaries, cost budgets, human confirmation, log tracing and abnormal termination.

**Risks and open questions:** The OpenAI page returned 403 to a PowerShell check but is readable through web search, and the official PDF downloads normally; the model is still a preview and its capabilities should not be treated as generally available.

### 3. Cursor: How Notion used the Cursor SDK to embed coding agents
- Sources: [Cursor blog](https://cursor.com/blog/notion)
- Type: Blog / Engineering case study
- Rating: ★★★★☆
- Summary: Notion embedded the Cursor SDK into its collaboration product so users can delegate a coding agent directly from a doc, thread or database issue and end up with a PR.

**Why it matters:** This is a good sample of agent product form: the agent is no longer just chatting with engineers in the IDE but entering team collaboration surfaces. Notion owns the context and the surface; Cursor owns the agent engine, sandbox, model routing, tool use and remote MCP.

**Key points:**
1. The integration approach is a thin adapter: a Notion thread maps to a Cursor agent, and each message maps to one agent run.
2. The user experience has to be observable and recoverable: follow-up runs stream progress to the user over SSE, and after a disconnect the client can resume from the last event.
3. Real usability depends on context and tools: through remote MCP, Cursor can read and write the Notion workspace and adapt to tasks via templates, skills, subagents and custom triggers.

**What it means:** A good agent is not an isolated window but "a delegation entry point in the existing workflow + a visible execution process + a PR or other change artifact + human acceptance".

**Risks and open questions:** Embedded agents like this must handle repo permissions, MCP permissions, PR attribution, failure recovery and sensitive-data boundaries.

## Open source worth a look

1. Project: omnigent-ai/omnigent
   GitHub: [omnigent-ai/omnigent](https://github.com/omnigent-ai/omnigent)
   Stars: 5,134
   What it solves: a meta-harness on top of Claude Code, Codex, Cursor, Pi and custom agents that unifies orchestration, policy, security sandboxing, cost control and multi-user collaboration.
   Why it's worth a look: it captures today's main thread: the future is not a single agent but a management layer over many harnesses, models, permissions and sessions.
2. Project: vercel/eve
   GitHub: [vercel/eve](https://github.com/vercel/eve)
   Stars: 2,804
   What it solves: filesystem-first durable AI agents, putting instructions, tools, skills, channels and schedules in fixed directories so agents are easier to inspect, extend and run.
   Why it's worth a look: it is a good way to understand that "an agent is not a prompt but a repo-native workflow primitive".
3. Project: agentclientprotocol/agent-client-protocol
   GitHub: [agentclientprotocol/agent-client-protocol](https://github.com/agentclientprotocol/agent-client-protocol)
   Stars: 3,515
   What it solves: standardizes communication between editors/clients and coding agents so that different IDEs and different coding agents can interoperate.
   Why it's worth a look: like MCP, ACP is an important protocol layer for understanding the agent engineering ecosystem; one connects tools, the other connects clients/editors.
