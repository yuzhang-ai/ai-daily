### 1. Zhipu: GLM-5.4 launched, first Loop Transformer flagship opens to Coding Plan
- Sources: [Official technical blog](https://z.ai/blog/glm-5.4); [Official docs](https://docs.bigmodel.cn/cn/guide/models/glm-5.4); [Hacker News thread](https://news.ycombinator.com/item?id=50609685); [Simon Willison's note](https://simonwillison.net/2026/Nov/23/glm-54/)
- Type: Model release
- Rating: ★★★★★
- Summary: Zhipu released GLM-5.4 on November 23, 2026, its first flagship model built on the Loop Transformer architecture, opened to all GLM Coding Plan users, with API access and weights to follow safety evaluations.
- Key figure: 28 layers × 2 loops | looping intermediate layers on an ~750B base model

**Why it matters:** In a standard Transformer, each layer executes computation only once during forward propagation; in contrast, a Loop Transformer runs a group of weight-shared layers through multiple loops, deepening the network without increasing parameter count. The concept of weight-shared depth was proposed as early as the 2018 Universal Transformer, and recent research on recurrent depth has mostly been validated at small scale; however, recurrent models pre-trained from scratch often lag behind non-shared models under equivalent compute budgets. Rather than pre-training from scratch, Zhipu adapted a pre-trained base into a Loop Transformer via continued training, scaling the recurrent architecture to an ~750B base model and prioritizing access for subscription products.

**Key points:**
1. Architectural changes and engineering implementation: The official blog notes that GLM-5.4 loops 28 layers 2 times on an ~750B GLM-5 base model, managing deployment costs through three modifications: Gated Progressive Updates introduces per-token independent gating to establish global context and write conservatively in the first pass, before deploying full updates in the second pass; Hybrid KV Cache combines cross-loop sharing with local sliding windows, so that additional loops consume only a single sliding window of KV cache; Sparse Attention Index Reuse directly reuses sparse attention indices generated in the first pass during the second pass, eliminating the computational overhead of secondary indexing.
2. Broad coding and self-reported performance: Official documentation indicates the model adds visual understanding capabilities, with input modalities spanning video, image, text, and files, outputting text with a 1M context window and maximum output of 128K, targeting "broad coding" across video, gaming, 3D, and mechanical design. In internal vendor evaluations across 200 real-world programming scenarios, Zhipu claims its overall coding experience ranks at the top among evaluated domestic models, with standout performance in visual coding, visual reproduction, and long-horizon tasks; in a 30B iso-parameter controlled benchmark, under identical parameters and ~10% more total training compute, average output length decreased by 10–14% across most benchmarks including GPQA-Diamond and MMLU-Pro; official figures state off-peak inference throughput reaches up to ~200 tokens/s, maintaining 70–80 tokens/s during peak hours.
3. Available channels and community feedback: The model is currently accessible via GLM Coding Plan, ZCode, and Z.ai Chat; official documentation notes that users with weekly quotas receive 1.5× the quota for GLM-5.4 compared to GLM-5.3; Simon Willison noted in his November 23 note that the model is not yet available via the regular API, and that he accessed it via a Coding Plan API key. The official blog states plans to responsibly open-source weights after completing safety hardening, with the API also opening following safety evaluations, while acknowledging the model is prone to entering overly extended "marathon thinking" loops; the related Hacker News thread reached approximately 1,031 points.

**What it means:** On the technical trajectory of recurrent depth and Loop Transformers, the 2018 Universal Transformer first proposed weight-shared depth; recently, Thinking Machines releasing Inkling 2 Mini weights (3.4B active parameters, looping intermediate layers 3 times) set a precedent for downloadable models, with the previous iteration being Zhipu's own GLM-5.3. Zhipu's new advance today lies in pushing the loop architecture to flagship scale on an ~750B base model, opening it first to subscription users through Coding Plan, ZCode, and Z.ai Chat rather than releasing weights first. Assessment: Loop layers have thus moved from downloadable small-model experiments into larger flagship subscription products; however, the gains accompanied by ~10% more training compute in the 30B iso-parameter comparison cannot be directly extrapolated to mean the 750B flagship has achieved equivalent returns with the same increase, and the regular API and weights remain unreleased.

**Risks and open questions:** Zhipu's claims that its intelligence level rivals models in the 2T–3T parameter range, and that it ranks at the top across 200 coding scenarios, are vendor self-evaluations and claims that have not been verified by independent third-party benchmarks. The official blog acknowledges the limitation that the model can fall into extended "marathon thinking." The ~750B figure refers to the base model scale rather than a confirmed total parameter count. Currently, regular API access and weights have not been publicly released, so external general developers still cannot directly download weights or deploy via a general API.

### 2. OpenAI: GPT-6.2 enters ChatGPT conversation page, fine-tuned for everyday chat

- Type: Product update
- Rating: ★★★★☆
- Summary: GPT-6.2, which entered the API on November 18, began rolling out on November 23, 2026 to ChatGPT conversation pages in a version optimized for everyday conversation.
- Key figure: 71.7% | official score on chat image understanding benchmark (vs. 47.4% for GPT-6)

**Why it matters:** GPT-6.2, which arrived in the API on November 18, began rolling out to the ChatGPT conversation page today. Prior to this, competitors such as Google had long deployed their leading flagship models to the primary interaction entry points of consumer chat, whereas OpenAI had previously made the GPT-6.2 series available only via the developer API. The ChatGPT release notes published on November 23, 2026 indicate that OpenAI has begun rolling out a conversation-optimized version powered by GPT-6.2 Sol to Plus, Pro, Business, and Enterprise users, placing the capabilities of its new-generation base model directly into the hands of everyday interactive users.

**Key points:**
1. Rollout scope and version positioning: The release notes explicitly state that GPT-6.2 in ChatGPT is powered by a version of GPT-6.2 Sol specifically tuned for everyday conversation; this update is strictly limited to the ChatGPT Chat experience, with models powering Work and Codex not included in this change; Enterprise availability depends on each workspace administrator's configuration.
2. Conversational capabilities and self-reported metrics: The official release notes state that the new model is better at handling complex requests requiring detailed instruction following or web browsing, and is better at proactively asking follow-up questions when appropriate (for instance, when asked whether an item is on sale, the model will offer to notify the user when the price drops). Internal self-test data shows that in chat interface evaluations, image understanding improved from 47.4% in GPT-6 to 71.7%; hard instruction-following scores rose from 62.5% to 78.1%; under the lowest reasoning setting, the internal expert-level task score reached 65% (compared to 52% for GPT-6); across all four reasoning settings in an internal version of BrowseComp, it outperformed GPT-6, with Extra high reaching approximately 64.5% versus 54.4%.
3. Safety policies and youth protections: The official notes state that youth safety evaluation results improved significantly, with the greatest gains in areas such as emotional dependence, eating disorders, age-restricted goods/services, and dangerous activities; in policy compliance evaluations on difficult conversations, responses adhered to safety policies at a rate of 91–94%, significantly higher than GPT-6's 77–80%.

**What it means:** In the competitive race for consumer chat products, rivals like Google had already set flagship models as the primary chat entry point; OpenAI initially launched the 6.2 series in the API on November 18, and today pushed the Sol version optimized for everyday conversation to the main Chat conversation page. Assessment: This allows end subscribers to experience the updated multimodal understanding and web-browsing follow-ups without writing code or calling APIs; however, because the update is strictly confined to main Chat and not extended to Work or Codex coding environments, there is no direct change for users who rely on programming and deep automation workflows.

**Risks and open questions:** Scores such as 71.7% in image understanding, 78.1% in instruction following, and BrowseComp are all OpenAI internal chat page evaluation results, without independent third-party comparative testing. Final availability for Enterprise users depends on whether administrator backend policies are enabled. Models in Work and Codex scenarios were not upgraded in this release.

### 3. Google DeepMind: Uses Gemini 4 agents to improve quantum algorithms, open-sources Lean verification library
- Sources: [DeepMind blog](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/); [GitHub repository](https://github.com/google-deepmind/formal-quantum-computation)
- Type: Research
- Rating: ★★★★☆
- Summary: Google DeepMind and Google Quantum AI announced on November 23, 2026 that they used teams of Gemini 4 agents to improve known quantum algorithms with formal proofs in Lean, while open-sourcing the verification codebase.
- Key figure: 11.8× | reported compute cost reduction for inertial confinement fusion circuits

**Why it matters:** On November 23, 2026, DeepMind published research authored by Sergey Shirobokov, Ben Jaderberg, Ryan Babbush, and colleagues, announcing a collaboration with Google Quantum AI that uses teams of Gemini 4 agents to improve known quantum algorithms into more efficient quantum circuits, mathematically formally verifying each result with the Lean interactive theorem prover. Quantum hardware remains in its early stages; even with optimal algorithms, the compute and qubit resources required for scientific simulations often exceed the capabilities of early error-corrected hardware, and complex circuits cannot be fully simulated on classical computers. This work explores a collaborative paradigm in which agents autonomously optimize algorithms while formal verification strictly enforces correctness.

**Key points:**
1. Multi-agent collaboration and formal verification flow: The study configured independent agent teams to search for algorithmic improvements on individual problems; proposed optimizations had to pass Lean formal proofs before being committed to a shared notebook, and teams exchanged and debated ideas in virtual meetings every four hours, progressively driving down compute overhead through continuous iteration.
2. Circuit optimization and resource reductions (all as reported in the post): In computations related to inertial confinement fusion properties, compute cost (a metric combining qubit count and operations) was reduced to 1/11.8 of the baseline (an 11.8× improvement), with required error-corrected qubit memory dropping from 5,650 to 4,338 qubits; quantum simulation costs for common photoactive molecules fell to 1/8; Cytochrome P450 enzymes used in drug metabolism achieved a 2.5× improvement, with memory reduced from 481 to 333 qubits; additionally, a specific implementation of Grover's algorithm achieved a 2.57× speedup, and an arcsin subroutine for loading numerical values achieved a 290× speedup.
3. Open-source library and scientific limitations: The team open-sourced a Lean 4 quantum algorithm library based on quantum Hoare logic with classical variables, problem descriptions, and verified solutions at google-deepmind/formal-quantum-computation. The repository uses an Apache-2.0 license, was created on November 14, 2026, and recorded 32 stars when queried via the GitHub API on November 24, 2026. DeepMind noted in the post that applying these algorithms to scientific simulations may still demand resources beyond what early error-corrected quantum computers can provide.

**What it means:** On the technical path combining formal verification and AI, this newsletter reported on November 23 on the Lean community's joint certification of the Riemann Hypothesis formal proof, which was community kernel verification of an external proof proposed by a human (who stated it was done in collaboration with Claude); today, DeepMind locked in agent-searched algorithmic improvements with the Lean proof assistant inside a frontier lab and open-sourced the complete verification toolchain. Assessment: This demonstrates the guardrail value of formal verification in domains lacking physical hardware for direct execution verification, transforming long-cycle manual circuit optimization into mathematically bounded automated search; however, it must not be overstated as AI having "solved" quantum computing, as scientific simulation deployment remains constrained by the progress of underlying error-corrected hardware.

**Risks and open questions:** The optimization gains listed in the blog, such as 11.8× and 290×, are self-reported by DeepMind and have not been independently tested against external benchmarks. The team explicitly acknowledged that even with these optimizations, resources required for practical scientific simulations may still exceed early error-corrected quantum hardware capabilities. The open-source repository was created on November 14, 2026 and had only 32 stars as of November 24, 2026; the generalizability of the toolchain across broader quantum domains awaits further adoption and scrutiny by the academic community.
