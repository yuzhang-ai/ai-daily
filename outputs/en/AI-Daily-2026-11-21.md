### 1. Google: The Antigravity desktop app can reach a remote Linux host over SSH
- Sources: [Docs](https://antigravity.google/docs/ssh); [Official account](https://x.com/antigravity/status/2123476398601908551)
- Type: Product update
- Rating: ★★★★☆
- Summary: The Antigravity desktop app can now use the local OpenSSH client to reach a user's own 64-bit Linux host, with projects and agents running there; the remote processes keep going after the window closes or the laptop sleeps.
- Image: ![The Open SSH Host dialog in the Antigravity desktop app, with recent hosts and SSH config entries](images/2026-11-21/1-antigravity-ssh.png) (Image: Google)
- Key figure: 2.33.0 | minimum desktop app version

**Why it matters:** The official account's post has `created_at` 2026-11-19T18:00:00Z, 02:00 on November 20 in Beijing time. The text says native SSH is now available in the desktop app, and names it as a connection method besides Remote Control. The docs page has no `datePublished`. The docs split remote work into three rows: over SSH, agents run on the user's own Linux machine, the client is the desktop app, and the host needs no extra install; Remote Control uses a browser to drive the user's own desktop or server; Remote Agents, for Pro and Ultra, run in a Google-managed environment. Editors that place a workspace on remote Linux over SSH already include VS Code and Cursor. Today's addition is the third option inside the Antigravity desktop app: the host is the user's Linux machine, and agents there continue after the local window closes or the laptop sleeps.

**Key points:**
1. The local computer needs Antigravity App 2.33.0 or newer, on macOS, Windows, or Linux, with OpenSSH on PATH or `ANTIGRAVITY_SSH_BIN` set. The remote side is 64-bit Linux only, x86_64 or arm64, glibc 2.26 or newer. The docs give Ubuntu 18.04+, Debian 10+, and RHEL 8+ as examples. macOS, Windows, and musl Linux (Alpine, for example) cannot be the remote host. The host and any jump host need `AllowTcpForwarding yes` or `local` in `sshd_config`.
2. Each host opens a window titled `SSH: <host>`. Projects, Git worktrees, the terminal, skills, rules, hooks, MCP, and plugins load from directories on the host. Closing the window disconnects SSH. The remote server and agents keep running and can be reattached. On laptop sleep or a dropped network, the client retries while the host processes stay up. `Stop SSH Server…` is what stops the agents, sidecars, and server on the host.
3. The same page lists differences from a local window: the side-panel browser is not shown, and http links open in the local default browser; `/browser` attaches to Chrome on the remote host with remote debugging enabled, not to the local computer; camera and screen access stay disabled; voice asks whether that host may use the microphone.

**What it means:** Putting a coding agent on a remote machine already has two rows in Antigravity's own docs: Remote Control drives the desktop at hand, and Remote Agents place the task in a Google-managed environment. VS Code and Cursor have long attached a workspace to Linux over SSH. What this desktop app adds is a third path, where the host is the user's own Linux machine and the task is still there after the laptop lid closes. The people affected are those who already have a Linux host that meets the glibc line and a desktop app at 2.33.0. The remote side is not macOS or Windows. Pro and Ultra remain the condition on the managed Remote Agents row, not a price for this SSH path.

**Risks and open questions:** "Now available" comes from the official account's post at 02:00 Beijing time on November 20. The docs have no publish timestamp, and they do not say every account can see 2.33.0 the same day. Host keys, port forwarding, glibc, and an executable `$HOME` are conditions before a connection succeeds. Agents that keep running after the window closes are not the same as inference staying on the user's computer, and not the same as an isolated host. Camera and screen stay disabled in an SSH window, which is a limit the docs state.

### 2. Thinking Machines: Inkling 2 Mini weights are out, with 3.4B active parameters
- Sources: [Model card](https://huggingface.co/thinkingmachines/Inkling-2-Mini); [Hugging Face post](https://huggingface.co/blog/inkling2mini); [Tinker playground](https://tinker.thinkingmachines.ai/playground); [Inkling 2 Small](https://huggingface.co/thinkingmachines/Inkling-2-Small)
- Type: Model release
- Rating: ★★★★☆
- Summary: Thinking Machines released the Apache 2.0 weights for the multimodal model Inkling 2 Mini: 26.4B total parameters, 3.4B active, a 1M-token context, image and text in, text out.
- Image: ![Inkling 2 Mini's loop: layers 6 through 17 share weights and run three times](images/2026-11-21/2-inkling-arch.png) (Image: Hugging Face)
- Key figure: 3.4B | active parameters; 26.4B total

**Why it matters:** The model card dates the release November 20, 2026. The `upload model` commit is 2026-11-20T22:02:14Z, 06:02 on November 21 in Beijing time. The previous model in the family, Inkling 2 Small, uploaded weights at 2026-11-12T19:53:15Z, 03:53 on November 13 in Beijing time. Its card says 594B total and 17B active. Mini's checkpoint is about 20GB, in NVFP4 and MXFP8. The card recommends at least 32GB of memory on Apple silicon, at least 32GB of VRAM on other GPUs, and says it can run on one NVIDIA DGX Spark. Local inference lists transformers, SGLang, vLLM, llama.cpp, MLX, Llama App, and Ollama. The only output is text.

**Key points:**
1. The architecture is a 24-layer decoder. The middle 12 layers run three times on shared weights, so each token gets 48 layer applications while the weights stay at 24 layers. Each layer routes a token to 8 of 128 experts. The card says 26.4B total and 3.4B active, and notes that each extra loop pass adds about 1.0B effective active parameters, for 5.4B effective active parameters after three passes. The comparison table writes activated/total as 5/26. Qwen3.8-27B beside it is 27/27, and Gemma 4 31B is 31/31. Context goes up to 1M tokens.
2. On the card's comparison table, AA Index v5.0 is 20.1 for both Mini and Qwen3.8-27B, 4.4 for Gemma 4 31B, 6.3 for Muse Glimmer, and 13.6 for Nemotron 3.5 Super VL. On Terminal-Bench v4.0 with mini-swe-agent v2.4.6, Mini and Qwen3.8-27B are both 5.6%. On Terminal-Bench v2.1 with pi v0.83.0, Mini is 71.6% and Qwen3.8-27B is 73.0%. Those two rows are not the same terminal benchmark.
3. Inference is available in the Tinker playground. The same day's research checkpoint is `thinkingmachines/TML-d24-varloop-research`, also Apache 2.0, and the loop count can be changed. The Hugging Face post says that 1 or 2 passes run faster, and that they have not evaluated that setting in depth.

**What it means:** On the line of open-weight local models, Inkling 2 Small first put up a 594B checkpoint with 17B active parameters. The card's side-by-side is with dense models around 30B, Qwen3.8-27B and Gemma 4 31B. Mini adds a checkpoint that fits on a 32GB machine, and writes the effective active count as 5.4B by sharing weights across three passes. The judgment stays inside the table: the index is a tie, and the two terminal rows are one tie and one loss, not a lead on every task. Someone switching a local model has to match the harness and the version on that row. An independent retest is not in the table yet.

**Risks and open questions:** The scores are filled in by Thinking Machines. This issue did not rerun them. Some cells are blank. Misbehavior, Covert misbehavior, and Destructive actions in the safety table are marked internal. The shader and napkin examples in the Hugging Face post are demos, not rows in the table. The 5.4B effective-active figure is for three passes. The post says the research checkpoint has not been evaluated in depth after the pass count changes. The card lists English and general multilingual support, and does not give a separate Chinese score.

### 3. Ideogram: Image model 4.6 is available, with output up to 4K
- Sources: [Model page](https://ideogram.ai/models/4.6); [Official account](https://x.com/ideogram_ai/status/2123461101224624402); [4.5 model page](https://ideogram.ai/models/4.5)
- Type: Model release
- Rating: ★★★★☆
- Summary: Ideogram 4.6 is available in the app and the API for Generate and Precise Edit, with 2K and 4K output; Very low quality stops at 2K, and a High-quality 4K edit is $0.60 per image.
- Key figure: 4K | output cap; Very low stops at 2K

**Why it matters:** The model page dates the release November 19, 2026. The official account's post has `created_at` 2026-11-19T16:59:13Z, 00:59 on November 20 in Beijing time, and the text says precise editing is now in native 4K. The 4.5 model page describes four quality modes at native 2K. The 4.6 page says it supports 2K and 4K, Very low stops at 2K, and Precise Edit keeps the source image's dimensions. Generate takes up to five reference images. Precise Edit can take a mask; without one, the change is described in text. The API endpoints are Generate and Precise Edit.

**Key points:**
1. The price table is per image, in US dollars. Very low: $0.008 to generate at 2K and $0.008 to edit at 2K, with dashes for both 4K cells. Low: $0.03, $0.06, $0.03, and $0.06 for generate 2K, generate 4K, edit 2K, and edit 4K. Medium: $0.06, $0.12, $0.06, and $0.20. High: $0.10 to generate at 2K, $0.20 to generate at 4K, $0.22 to edit at 2K, and $0.60 to edit at 4K. The page says the API starts at $0.008 per image for Very low quality at up to 2K.
2. The page cites Rapidata's Multi-step Image Edit overall leaderboard, snapshot dated November 17, 2026. The evaluated setup is Ideogram 4.6 Precise Edit at High quality, score 1,892 ± 32, ranked first. On the same table Ideogram 4.5 is 1,866 ± 30, Seedream 5.5 is 1,805 ± 29, FLUX 3 Image is 1,697 ± 27, Muse Image is 1,406 ± 22, MAI-Image-2.6 is 1,299 ± 22, and Qwen-Image-2.1-Pro (Thinking) is 1,291 ± 21. The 4.6 and 4.5 intervals overlap.
3. The page FAQ says that, on five High-quality editing tasks shown on that page, 4.6 produces more usable results than 4.5. The five are character consistency, exact color, product detail, product shots, and masked edits. The same passage says to compare both models on your own images and requests before replacing an established workflow.

**What it means:** On the line of multi-step image editing, Ideogram 4.5 stops at native 2K. The same Rapidata snapshot also lists Seedream, FLUX, Muse, MAI-Image, and Qwen-Image. What 4.6 adds is the 4K tier, and a price list split by quality, resolution, and whether the call generates or edits. The gap versus 4.5 sits inside the error ranges the page prints, and the snapshot date is two days before the release date the page states. Someone switching the API should read the High-quality 4K edit as $0.60 per image, not the $0.22 of a 2K edit.

**Risks and open questions:** The ranking and the five-task comparison both come from Ideogram's own page. This issue did not rerun them. 1,892 ± 32 and 1,866 ± 30 overlap, so the table does not show a stable gap over 4.5. The snapshot is November 17, and the model page's release date is November 19. Very low has no 4K price. Precise Edit keeping the source dimensions does not mean every 4K edit changes the pixel size.
