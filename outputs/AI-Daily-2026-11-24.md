### 1. 智谱: GLM-5.4 上线，首款 Loop Transformer 旗舰对 Coding Plan 开放
- 来源链接：[官方技术博客](https://z.ai/blog/glm-5.4)；[官方文档](https://docs.bigmodel.cn/cn/guide/models/glm-5.4)；[Hacker News 讨论](https://news.ycombinator.com/item?id=50609685)；[Simon Willison 笔记](https://simonwillison.net/2026/Nov/23/glm-54/)
- 类型：模型发布
- 推荐指数：★★★★★
- 一句话总结：智谱于 2026 年 11 月 23 日发布首款建立在 Loop Transformer 架构上的旗舰模型 GLM-5.4，已向 GLM Coding Plan 全量用户开放，API 与权重将在安全评估后提供。
- 关键数字：28 层 × 2 次 | 在约 750B 规模基座上循环中间层

**为什么重要：** 在标准 Transformer 中，每一层在前向传播中只执行一次计算；而 Loop Transformer 让一组共享权重的层循环多轮，在不增加参数量的条件下加深网络。权重共享深度的设想早在 2018 年的 Universal Transformer 中便已提出，近年关于循环深度的研究也多在小规模验证；但从头预训练的循环模型在同等算力预算下往往落后于非共享模型。智谱在此次发布中并未从头预训练，而是把已预训练基座通过继续训练改造成 Loop Transformer，将循环架构拓展至约 750B 规模基座，并优先面向订阅产品开放。

**核心观点：**
1. 架构改动与工程实现：官方博客写明，GLM-5.4 在约 750B 规模的 GLM-5 基座上对 28 层循环 2 次，并通过三项改动控制部署成本：Gated Progressive Updates 引入逐 token 独立门控，在第一轮建立全局上下文并保守写入，第二轮展开完整更新；Hybrid KV Cache 采用跨循环共享与局部滑动窗口结合，使额外循环仅消耗一个滑动窗口的 KV 缓存；Sparse Attention Index Reuse 在第二轮直接复用首轮生成的稀疏注意力索引，消除了二次索引计算开销。
2. 泛编程与自测表现：官方文档显示，模型新增视觉理解能力，输入模态包含视频、图像、文本与文件，输出为文本，上下文窗口为 1M，最大输出为 128K，应用方向定位于涵盖视频、游戏、3D 与机械设计的「泛 Coding」。在厂商内部开展的 200 个真实编程场景评测中，智谱自称其整体编程体验在参评国产模型中位居前列，并在视觉 Coding、视觉复刻与长程任务中表现突出；在 30B 等参对照自测中，在参数相同且总训练计算约多 10% 条件下，GPQA-Diamond 与 MMLU-Pro 等多数基准上的平均输出长度下降 10–14%；官方自述低峰推理吞吐最高约 200 tokens/s，高峰保持 70–80 tokens/s。
3. 可用渠道与社区反馈：模型目前已在 GLM Coding Plan、ZCode 和 Z.ai Chat 提供可用入口，官方文档注明有周限额的用户使用 GLM-5.4 时额度提升至 GLM-5.3 的 1.5 倍；Simon Willison 在 11 月 23 日笔记中说明该模型尚不可走常规 API，他通过 Coding Plan 的 API 密钥完成调用。官方博客表示计划在完成安全加固后负责任地开源权重，API 亦在安全评估后开放，并承认该模型容易进入过长的「marathon thinking」循环；Hacker News 上的相关讨论约为 1,031 分。

**这意味着什么：** 在循环深度与 Loop Transformer 这一技术方向上，2018 年 Universal Transformer 最先提出权重共享深度，近期 Thinking Machines 放出 Inkling 2 Mini 权重（激活 3.4B，中间层循环 3 次）是做成可下载模型的先例，上一版则是智谱自家的 GLM-5.3。智谱今天的新进展在于把循环架构推向约 750B 规模基座的旗舰级别，并先通过 Coding Plan、ZCode 和 Z.ai Chat 向订阅用户开放，而不是先放权重。判断：循环层由此从可下载的小模型实验，走进了更大的旗舰订阅产品；但 30B 等参对照里约多 10% 训练计算所伴随的收益，不能直接外推为 750B 旗舰已经用同样增幅换到了同等效果，常规 API 与权重也仍未开放。

**风险与待验证：** 智谱宣称其智能水平可比拟 2T–3T 参数量级模型，以及在 200 个编程场景中居前列，均属官方自测与自称，尚无独立第三方评测验证。官方博客承认模型存在长时间陷入「marathon thinking」的局限。约 750B 指基座规模而非确定的总参数量。目前常规 API 与权重尚未公开发布，外部普通开发者仍无法直接下载权重或通过通用接口部署。

### 2. OpenAI: GPT-6.2 进入 ChatGPT 对话页，面向日常对话微调
- 来源链接：[ChatGPT 更新说明](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- 类型：产品更新
- 推荐指数：★★★★☆
- 一句话总结：11 月 18 日已经进入 API 的 GPT-6.2，于 2026 年 11 月 23 日开始向 ChatGPT 对话页推送面向日常对话优化的版本。
- 关键数字：71.7% | 官方称对话页图像理解测试成绩（对比 GPT-6 的 47.4%）

**为什么重要：** 11 月 18 日已经进入 API 的 GPT-6.2，今天开始向 ChatGPT 对话页推送。在此之前，Google 等厂商早已将各自的当家旗舰模型部署于消费级聊天的主交互入口，而 OpenAI 先前仅在开发者 API 中开放了 GPT-6.2 系列。2026 年 11 月 23 日发布的 ChatGPT 更新说明显示，官方开始向 Plus、Pro、Business 和 Enterprise 档位用户推送由 GPT-6.2 Sol 驱动的对话优化版本，将新一代基座的能力直接交到日常交互用户手中。

**核心观点：**
1. 推送范围与版本定位：更新说明明确写明，ChatGPT 中的 GPT-6.2 由 GPT-6.2 Sol 的一个版本驱动，专门为日常对话进行了调整；此次更新严格限于 ChatGPT 的 Chat 对话体验，为 Work 和 Codex 提供动力的模型不在此次变更范围内；Enterprise 档位的可用性取决于各工作区管理员的配置。
2. 对话能力与自测指标：官方更新说明写道，新模型更擅长处理需要遵循详细指令或联网查找信息的复杂请求，且更懂得适时向用户追问（例如询问某物品是否打折时，模型会主动提议在降价时发送通知）。官方自测数据显示，在对话页评测中，图像理解成绩从 GPT-6 的 47.4% 提升至 71.7%；高难度指令遵循得分从 62.5% 升至 78.1%；在最低推理设置下，内部专家级任务评测得分为 65%（GPT-6 为 52%）；内部版 BrowseComp 的四档推理设置均超过 GPT-6，其中 Extra high 约为 64.5% 对 54.4%。
3. 安全政策与青少年防护：官方说明称青少年安全评测结果显著提高，最大改善出现在情感依赖、饮食障碍以及年龄限制商品/服务与危险活动等领域；在针对困难对话的政策符合评测中，回复符合安全政策的比例为 91–94%，显著高于 GPT-6 的 77–80%。

**这意味着什么：** 在消费级聊天产品的竞争路线上，Google 等对手此前已把旗舰模型设为主对话入口；OpenAI 此前在 11 月 18 日率先在 API 推出 6.2 系列，今天则是把针对日常对话优化后的 Sol 版本推向主 Chat 对话页。判断：这使得终端订阅用户在无需编写代码或调用 API 的情况下即可体验新版的多模态理解与联网追问；但由于该变更被严格隔离在主 Chat 之中，并未同步扩展至 Work 与 Codex 代码场景，对于依赖编程与深度自动化工作流的用户而言并无直接变化。

**风险与待验证：** 图像理解 71.7%、指令遵循 78.1% 以及 BrowseComp 等分数均为 OpenAI 官方对话页内部评测结果，未经独立第三方对比测试。Enterprise 用户的最终可用情况取决于管理员后台策略是否开启。Work 和 Codex 场景下的模型未在此次更新中升级。

### 3. Google DeepMind: 用 Gemini 4 agent 改进量子算法，并开源 Lean 验证库
- 来源链接：[DeepMind 博客](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/)；[GitHub 仓库](https://github.com/google-deepmind/formal-quantum-computation)
- 类型：研究
- 推荐指数：★★★★☆
- 一句话总结：Google DeepMind 与 Google Quantum AI 于 2026 年 11 月 23 日公布，利用 Gemini 4 agent 团队改进已知量子算法并用 Lean 完成形式化证明，同时开源验证代码库。
- 关键数字：11.8× | 官方称惯性约束聚变相关电路的计算成本降幅

**为什么重要：** DeepMind 于 2026 年 11 月 23 日发布由 Sergey Shirobokov、Ben Jaderberg、Ryan Babbush 等人署名的研究，宣布与 Google Quantum AI 合作利用 Gemini 4 agent 团队改进已知量子算法，得到更高效的量子电路，并用交互式定理证明器 Lean 对每个结果完成数学形式化证明。量子硬件目前尚处于发展早期，即便采用最优算法，科学模拟所需的计算与量子比特资源仍常超出早期纠错硬件的能力，且复杂电路在经典计算机上难以完整仿真。该研究探索了利用 agent 自主优化算法并由形式化证明严格卡住正确性的协作范式。

**核心观点：**
1. 多 agent 协作与形式化验证流：研究设定独立的 agent 团队针对各个问题搜寻算法改进，提出的优化必须先通过 Lean 形式化证明无误后才写入共享笔记本，各团队每隔四小时在虚拟会议上交换与辩论想法，通过持续迭代逐步压低计算开销。
2. 电路优化与资源降幅（均为文中自述）：在惯性约束聚变相关性质计算中，计算成本（综合量子比特数与操作的指标）降至原先的 1/11.8（即 11.8 倍改善），所需纠错量子比特内存从 5,650 个降至 4,338 个；常见光敏分子的量子模拟成本降为 1/8；用于药物代谢的细胞色素 P450 酶（Cytochrome P450）实现 2.5 倍改进，内存从 481 降至 333 个量子比特；此外，特定实现的 Grover 算法获得 2.57 倍加速，用于载入数值的 arcsin 子例程获得 290 倍加速。
3. 开源库与科学局限：团队开源了基于经典变量量子 Hoare 逻辑的 Lean 4 量子算法库、问题说明及已验证解，仓库为 google-deepmind/formal-quantum-computation。该仓库采用 Apache-2.0 许可证，创建于 2026 年 11 月 14 日，GitHub API 于 2026 年 11 月 24 日查询记录为 32 star。DeepMind 同时在文中指出，若要将这些算法用于科学模拟，所需资源仍可能高于早期纠错量子计算机可能提供的水平。

**这意味着什么：** 在形式化验证与 AI 结合的技术路径上，本报 11 月 23 日刚报道了 Lean 社区对黎曼假设形式化证明的联合认证，那是社区对人类（自述与 Claude 合作）提出的外部证明进行内核核验；今天 DeepMind 则是在前沿实验室内部将 agent 搜索出的算法改进用 Lean 证明助手直接卡住，并公开了完整的验证工具链。判断：这展示了形式化验证在缺少物理硬件直接执行验证的领域所具备的护栏价值，将长周期的人工电路优化转变为受数学约束的自动搜索；但绝不能将其夸大为量子计算已被 AI 解决，科学模拟的落地仍受制于底层纠错硬件的发展进度。

**风险与待验证：** 博客中列出的 11.8 倍、290 倍等优化幅度均为 DeepMind 文中自述，未经独立外部基准检验。团队明确承认即使经过这些优化，实际科学模拟所需资源依然可能超过早期纠错量子计算机所能提供的能力。开源仓库创建于 2026 年 11 月 14 日，截至 2026 年 11 月 24 日仅有 32 star，工具链在更广泛量子领域的通用性仍待学术界进一步使用与检验。
