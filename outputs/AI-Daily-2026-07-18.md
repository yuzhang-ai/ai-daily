## 一、今日最值得关注的 3 条内容

### 1. OpenAI: A scorecard for the AI age + The Shift to Agentic AI

- 来源链接：[A scorecard for the AI age](https://openai.com/index/a-scorecard-for-the-ai-age/)；[How agents are transforming work](https://openai.com/index/how-agents-are-transforming-work/)；[论文 PDF](https://cdn.openai.com/pdf/5d1e1489-21c0-43e4-9d42-f87efdbf0082/the-shift-to-agentic-ai-evidence-from-codex.pdf)
- 本地文件：`outputs/sources/the-shift-to-agentic-ai-evidence-from-codex-2026-06-25.pdf`
- 类型：官方博客 / 论文 / AI Adoption / Agentic Work
- 推荐指数：★★★★★
- 一句话总结：OpenAI 把 AI 价值衡量从 token 单价拉回到“有用工作 / 成功任务成本 / 可靠性 / 规模化回报”，并用 Codex 真实使用数据说明：agentic AI 的单位不是一次聊天，而是一段可委派、可并行、可验收的工作流。

**为什么重要：**
这条很适合 AI 产品经理和 FDE 精读，因为它直接回答企业客户最关心的问题：不是“模型多强”，而是“这笔 AI 花费有没有变成可用成果”。OpenAI 最新 scorecard 提出 `Useful Intelligence per Dollar`，强调要看成功任务的完整成本，包括模型、工具调用、重试、人工 review 和返工。配套的 Codex 研究更关键：Codex 在 2026 上半年活跃用户增长超过 5 倍，非开发者增长最快；OpenAI 内部 Legal、Finance、Recruiting 等非技术团队也开始把 Codex 当作主要工作工具。这不是单点效率提升，而是工作组织方式变化。

**核心观点 3 条：**
1. AI ROI 不能只看 token 价格。便宜模型如果失败、重试、需要大量人工修正，最终未必便宜；更强模型如果一次交付可用结果，反而可能降低每个成功任务成本。
2. Agentic AI 的衡量单位是 `delegated workflow`。Codex 研究显示，重度用户会并行管理多个 agent、使用 skills，并把任务从“问答”推进到“生产性执行”。
3. 可靠性本身就是经济价值。OpenAI 建议把结果分成 `Ready to use`、`Needs correction`、`Needs escalation`，这比单纯 benchmark accuracy 更接近企业落地。

**这意味着什么：**
衡量 AI 工作流的更好方式是：定义一个业务工作流，设定完成标准，记录 AI 成本和人工 review 成本，统计一次通过率、返工率、升级人工率，然后证明这个流程可以规模化。FDE 面向客户时，也应该先帮客户选一个高价值 workflow，而不是一上来讲模型参数。

**风险与待验证：**
Codex 数据有明显 frontier bias：OpenAI 内部环境、员工 AI 熟练度、工具权限和使用成本都不代表普通企业。论文很有启发，但不能直接拿 99% token 占比或非开发者增长倍数去承诺客户 ROI。是否值得精读：是。

### 2. Google DeepMind: GDM AI Control Roadmap

- 来源链接：[DeepMind 官方博客](https://deepmind.google/blog/securing-the-future-of-ai-agents/)；[官方 PDF](https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/securing-the-future-of-ai-agents/gdm-ai-control-roadmap.pdf)；[arXiv](https://arxiv.org/abs/2607.13087)
- 本地文件：`outputs/sources/gdm-ai-control-roadmap-2026-07-13.pdf`
- 类型：官方博客 / 报告 / Agent Security / Governance
- 推荐指数：★★★★★
- 一句话总结：DeepMind 把 agent 安全从“相信模型对齐”推进到“假设 agent 可能出错甚至不可靠，然后用检测、预防、响应三层控制把风险关进系统边界”。

**为什么重要：**
Agent 越能干，越会接触代码库、内部系统、文件、权限和生产环境。DeepMind 的 roadmap 不是泛泛讲安全，而是给出一套面向高能力 agent 的控制工程：把 AI agent 当成可能误解目标、过度执行、甚至潜在不可信的内部操作者来设计防线。它借鉴 MITRE ATT&CK 做威胁建模，提出 Detection D1-D4、Prevention/Response R1-R3，并列出 15 类分层防御。对 FDE 来说，这几乎可以直接转成企业 agent 上线前的安全检查框架。

**核心观点 3 条：**
1. Alignment 不够，系统级 containment 才是落地关键。沙箱、端点安全、prompt injection resistance、权限分级和实时阻断要成为 agent 产品默认能力。
2. 防御强度要随模型能力升级。能逃避检测、能执行复杂攻击或能跨系统行动的 agent，不能继续沿用“事后看日志”的弱控制。
3. 监控指标要产品化。DeepMind 提到 coverage、recall、time-to-response，这三个指标可以直接改写成企业 agent 运维看板：监控覆盖多少任务，拦住多少异常，多快能人工接管。

**这意味着什么：**
以后做 Agent 产品，不只要画 happy path，还要画 risk path：Agent 读错需求怎么办？删除数据怎么办？拿到多余权限怎么办？工具返回恶意内容怎么办？

**风险与待验证：**
DeepMind 的 roadmap 是前沿实验室内部安全框架，不等于所有企业都要一次性实现 D4/R3。涉及真实客户数据时，必须默认最小权限、脱敏、审计和人工确认。是否值得精读：是。

### 3. Latent Space / Cursor: AI Engineering 进入 FDE、Loop、Skills 阶段

- 来源链接：[5 Trends That Defined AI Engineering at World’s Fair 2026](https://www.latent.space/p/aiewf26trends)；[Cursor x Coinbase 案例](https://cursor.com/blog/coinbase)；[Cognition Agentic MapReduce](https://devin.ai/blog/agentic-map-reduce)
- 类型：行业复盘 / 企业案例 / Agent Engineering
- 推荐指数：★★★★☆
- 一句话总结：2026 年的 AI Engineering 讨论已经从“agent 能不能工作”转向“如何把 agent 变成企业内可管理、可评估、可复制的系统”，FDE、outer loop、skills 和 whole-codebase reasoning 都在成为主线。

**为什么重要：**
Latent Space 对 AI Engineer World’s Fair 的复盘指出：FDE 不只是会调工具的人，而是帮客户把 AI 嵌进真实流程的人。文章提到今年讨论焦点从 AutoGPT 式自治幻想，转向 harness、context、evals、loops、skills、enterprise adoption。Cursor 的 Coinbase 案例则给了企业落地指标：超过 2400 名开发者使用 Cursor，75% PR 由 agent 创建，部分团队 idea 到 production 时间从 20 天降到 2 天以内。Cognition 的 Agentic MapReduce 又补上工程方法：全代码库任务不能靠一个 agent 到处 grep，要先确定性筛选，再分片并行，再 reduce 验证。

**核心观点 3 条：**
1. `Outer loop` 是人的新位置。Agent 可以跑 inner execution loop，但人要负责目标、约束、验收、风险和最终决策。
2. FDE 的价值在组织改造。客户要的不是“装一个 agent”，而是把需求、权限、上下文、工具、评估、ROI 和 champion 机制全部串起来。
3. Skills / rules / AGENTS.md 类文件正在成为复用单位。它们把资深工程师的工作流、质量门和上下文组织方式写成 agent 可调用资产。

**这意味着什么：**
下一阶段的重点是管理一组 agent 完成一个业务闭环：任务入口、上下文准备、分工、状态监控、人工审批、测试验证、上线复盘。

**风险与待验证：**
Cursor / Cognition 的案例都有供应商叙事，数据要当方向信号，不要当普遍承诺。Agentic MapReduce 的关键风险在 selector recall：如果确定性筛选规则漏掉文件，后面的并行 agent 再强也看不到。是否值得精读：是。

## 二、今日最重要的一个观点

> Agent 产品的核心壁垒正在从“让模型回答”变成“让工作可委派、可度量、可控制、可复用”。AI PM / FDE 要练的是把业务流程拆成 agent 能执行的工作流，再用 scorecard、control checklist、skills 和人工验收闭环证明它真的创造价值。

## 三、值得深入学习的开源项目

1. 项目名：microsoft/agentrc
   GitHub 链接：[microsoft/agentrc](https://github.com/microsoft/agentrc)
   Star 数：约 964
   解决什么问题：扫描代码库的 AI-readiness，生成面向 coding agents 的 instructions、evals、MCP 配置和 CI 漂移检查。
   为什么值得看：它把“给 Agent 准备上下文”产品化成可跑 CLI，非常适合学习如何从 repo 级别沉淀 AGENTS.md / copilot-instructions / eval。
2. 项目名：muratcankoylan/Agent-Skills-for-Context-Engineering
   GitHub 链接：[Agent-Skills-for-Context-Engineering](https://github.com/muratcankoylan/Agent-Skills-for-Context-Engineering)
   Star 数：约 17.3k
   解决什么问题：把 context engineering、harness engineering、multi-agent、memory、eval 等经验沉淀成 Agent Skills。
   为什么值得看：它贴近“skills 作为复用资产”的趋势，可以借鉴怎么把一套 AI 工作流写成 agent 能调用的知识包。
3. 项目名：trustgraph-ai/trustgraph
   GitHub 链接：[trustgraph-ai/trustgraph](https://github.com/trustgraph-ai/trustgraph)
   Star 数：约 2.3k
   解决什么问题：用 context graph / ontology / open standards 管理 agent 可用上下文，让知识像基础设施一样可版本化、可部署、可回滚。
   为什么值得看：它代表 RAG 之后更结构化的 context layer 思路，适合理解企业知识如何从“文档检索”升级到“可治理的 agent context”。
